# Think Before Coding

- State load-bearing assumptions explicitly before implementing — if uncertain, ask instead of guessing
- When a request has multiple plausible interpretations, present them and pick one with the user — don't silently choose
- Push back when a simpler approach exists or when the request implies unnecessary complexity — give the technical reason
- Stop when confused. Name precisely what's unclear and ask. Don't paper over confusion with plausible-looking code
- Every changed line should trace to the user's request — if you can't explain why a line is there, don't write it
